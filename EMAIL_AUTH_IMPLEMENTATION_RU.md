# Email-авторизация GorkyCode: инструкция по запуску

Это описание изменений в рабочей копии проекта. Оно написано для разработчика, который знает основы программирования, но пока не работал с FastAPI и SQLAlchemy.

## 1. Какой сценарий получится

- В обычном браузере пользователь обязан подтвердить email одноразовым кодом из письма.
- Сервер больше не создаёт веб-сессию только по случайному `client_id`.
- API чата, список событий, завершение событий, синтез речи, загрузка голоса и WebSocket требуют действующую сессию.
- Telegram, VK и MAX по-прежнему идентифицируют отправителя средствами своей платформы.
- Чтобы привязать бот к аккаунту с email, пользователь отправляет боту `/email адрес@example.com`, получает код по почте, затем отправляет `/emailcode адрес@example.com 123456`.
- Задачи хранятся за внутренним `users.id`, поэтому при привязке нового клиента старая история должна остаться у общего аккаунта.

## 2. Новые файлы

### `app/db/models/user_email.py`

SQLAlchemy-модель таблицы `user_emails`. Хранит подтверждённый email, владельца (`user_id`) и стабильный идентификатор веб-сессии (`web_identity_id`). Сам email не кладётся в токен.

### `app/db/models/email_challenge.py`

Модель таблицы `email_challenges`. Хранит HMAC-хеш одноразового кода, срок действия, количество попыток и к какой идентичности относится проверка. Открытый код в БД не сохраняется.

### `app/services/auth/email_sender.py`

Отправляет письма через HTTP API Resend. Использует уже имеющуюся в `requirements.txt` библиотеку `httpx`; отдельная Python-библиотека Resend не нужна.

### `app/interfaces/email_linking.py`

Общие функции, которыми пользуются обработчики Telegram, VK и MAX для запроса и подтверждения email-кода.

### `frontend/src/components/AuthPanel.tsx`

Форма ввода email и одноразового кода.

### `alembic/versions/0003_email_auth.py`

Миграция БД: создаёт таблицы для подтверждённых email и одноразовых кодов.

## 4. Настройка Resend

1. Создай аккаунт на <https://resend.com/>.
2. Добавь и подтверди домен, с которого приложение будет отправлять письма. Используй адрес отправителя на подтверждённом домене.
3. Создай API key в панели Resend.
4. Открой свой локальный `.env`. Если файл уже существует, **не заменяй его целиком** — добавь в конец только эти переменные:

```dotenv
RESEND_API_KEY=re_вставь_свой_ключ
EMAIL_FROM="GorkyCode <login@your-verified-domain.example>"
EMAIL_CODE_SECRET=вставь_отдельный_случайный_секрет
EMAIL_CODE_TTL_SECONDS=600
EMAIL_CODE_MAX_ATTEMPTS=5
EMAIL_CODE_COOLDOWN_SECONDS=60
```

В `EMAIL_FROM` замени адрес на адрес с твоего подтверждённого домена. Не коммить `.env` и никогда не вставляй в исходный код реальные секреты.

Сгенерировать случайный `EMAIL_CODE_SECRET` можно командой:

```powershell
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Скопируй получившуюся строку в `.env` как значение `EMAIL_CODE_SECRET`. Не используй для этого пароль от почты или API-ключ Resend.

## 5. Применение миграции и запуск

### Если запускаешь приложение локально в Windows PowerShell

Перейди в корневую папку проекта, активируй виртуальное окружение и установи зависимости, если ещё не установлены:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Проверь, что `.env` содержит правильный `DATABASE_URL`. Затем **до первого запуска новой версии приложения** примени миграцию:

```powershell
alembic upgrade head
```

После успешного завершения запусти приложение:

```powershell
python main.py
```

Если виртуальное окружение ещё не создано, сначала выполни `python -m venv .venv`, затем активируй его и установи зависимости.

### Если запускаешь через Docker Compose

Команда контейнера приложения уже сначала запускает `alembic upgrade head`, а затем `python main.py`. Добавь настройки Resend в `.env` и выполни:

```powershell
docker compose up --build
```

Не запускай новую версию приложения против рабочей базы до резервной копии. В текущем проекте `AUTO_CREATE_TABLES` включён по умолчанию для локального запуска, но предпочтительный путь для существующей БД — применить Alembic-миграцию до старта новой версии.

## 6. Как проверить вручную

### В браузере

1. Открой `http://localhost:8000`.
2. Вместо чата должна отображаться форма email.
3. Введи свой email и нажми «Получить код».
4. Проверь входящие и папку «Спам», введи шесть цифр из письма.
5. После успешного входа создай тестовую задачу, обнови страницу и проверь, что сессия восстановилась и задача осталась доступна.
6. Для проверки запрета анонимного доступа открой DevTools → Network: запрос `/api/chat` без заголовка `Authorization: Bearer ...` должен вернуть HTTP `401`.

### Связать существующий аккаунт Telegram/VK/MAX с email

В нужном личном чате с ботом отправь:

```text
/email your-address@example.com
```

Введи код из письма в этом же боте:

```text
/emailcode your-address@example.com 123456
```

После подтверждения бот и браузер должны работать с одним аккаунтом. Выполни тест: создай задачу из браузера, привяжи Telegram через email, затем попроси бота показать задачи.

### Сохранение старых анонимных задач

Если старая вкладка всё ещё хранит действительный подписанный веб-токен, новая форма отправит его при запросе/проверке кода, и код сможет перенести старые задачи в аккаунт подтверждённого email. Если токен уже истёк или удалён, сервер не может доказать, кому принадлежит анонимная история; автоматически переносить её только по введённому email небезопасно.

## 7. Как понимать файлы Python, если до этого писал на Go

- **Модель SQLAlchemy (`app/db/models/*.py`)** — Python-описание таблицы: поля класса соответствуют колонкам в БД.
- **Миграция Alembic (`alembic/versions/*.py`)** — пошаговое изменение схемы существующей БД. Создание файла модели само по себе не меняет реальную базу.
- **Репозиторий (`app/repositories/*.py`)** — слой запросов к БД. `select(...)` строит SQL-запрос, `session.add(obj)` добавляет объект для вставки, `await session.flush()` отправляет изменения в БД внутри текущей транзакции и получает ID, а `await session.commit()` фиксирует транзакцию.
- **Сервис (`app/services/*.py`)** — бизнес-логика: срок действия кода, проверка попыток, создание аккаунта и привязка идентичностей.
- **Роутер FastAPI (`app/interfaces/web/*.py`)** — HTTP-обработчик. Он принимает JSON, вызывает сервис и возвращает JSON/HTTP-статус.
- **`async def` и `await`** — асинхронные функции; они нужны, чтобы ожидание БД или почтового API не блокировало обработку других запросов.

## 8. Проверки проекта

Сначала можно проверить синтаксис Python:

```powershell
python -m compileall -q app tests
```

Затем запусти тесты (из корня проекта):

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты фронтенда:

```powershell
cd frontend
corepack pnpm install
corepack pnpm test
corepack pnpm build
```

В среде, где готовилась эта копия, `python -m compileall -q app tests` успешно проходил, а тесты веб-маршрутов и WebSocket дали `28 passed, 1 skipped`. Полный backend-набор не получилось проверить здесь: в среде отсутствуют пакеты из самого `requirements.txt`, включая `aiosqlite`, `aiogram`, `fakeredis` и `vosk`; также здесь не установлены зависимости фронтенда. Поэтому перед использованием в развёртывании обязательно прогони полный набор тестов в окружении с установленными зависимостями.

## 9. Что ещё необходимо перед production

Это первый вариант интеграции. Перед публичным запуском добавь ограничение частоты запросов не только по email, но и по IP/подсети на уровне приложения или reverse proxy, настрой мониторинг отказов почты и проверь ротацию `SESSION_SECRET`. Не включай секреты в логи. В текущей реализации пауза между отправками считается в пределах пары «email + клиентская идентичность», а не по IP; перед публичным запуском добавь глобальный лимит по email и лимит по IP/подсети на уровне приложения или reverse proxy. Проверь восстановление старых аккаунтов на копии БД, прежде чем применять к боевым данным.
