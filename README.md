Наш продукт - это голосовой ассистент, который работает **одновременно на 4-х платформах**, взаимодействовать с ассистентом можно как голосом, так и с помощью текста. В проект включены передовые AI-технологии и российские сервисы.
Наша команда сделала акцент на максимальной скорости работы, речь распознается в реальном времени, после чего, почти сразу, поступает ответ от языковой модели. Текстовый ответ и аудиоозвучка разделены, благодаря этой асинхронности исключаются задержки интерфейса.
В качестве основ брались российские технологии, такие как GigaChat API - для точности распознавания намерений пользователя и управлением задачами, а также SaluteSpeech от Сбера для более естественных ответов ассистента.

1. Классический чат-бот для быстрой отправки текстовых и голосовых сообщений.
2. Полноценное **мини-приложение (Mini App)** для удобного управления задачами.

## <a id="tech"></a>🛠 Выбранный стек технологий

[К содержанию](#toc)

- **Архитектура:** Монолит
- **Язык:** Python
- **Распознавание речи (STT):** Vosk — офлайн, официальный Python-биндинг [alphacep/vosk-api](https://github.com/alphacep/vosk-api)
- **Синтез речи (TTS):** SaluteSpeech через Cloud.ru Foundation Models (реальный голос), офлайн-резерв espeak-ng
- **Нейросеть (LLM):** GigaChat API (с вызовом тулзов / Function Calling)
- **База данных:** PostgreSQL
- **ORM & Миграции:** SQLAlchemy + Alembic
- **Кэш:** Redis (кэширование основных запросов)
- **Веб-фронтенд:** React 19, TypeScript, Vite, Tailwind CSS v4
- **Интерфейсы:**
  - Веб-интерфейс
  - Telegram-бот
  - Бот в MAX
  - Бот в VK

## 🚀 Быстрый старт
[К содержанию](#toc)

### 1. Локальный запуск

Нужны Python 3.11+, Node 22+ и pnpm 9 (`corepack enable` включит версию из `package.json`),
а также `ffmpeg` и `espeak-ng` — они нужны голосовому режиму и локальной озвучке.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

cd frontend && pnpm install && pnpm build && cd ..

cp .env.example .env
# чтобы не поднимать PostgreSQL и Redis, в .env достаточно указать:
#   DATABASE_URL=sqlite+aiosqlite:///./gorkycode.db
#   CACHE_ENABLED=false

python main.py
```

Приложение поднимает веб-интерфейс на `http://localhost:8000`, страница чата — `/`.
SQLite и отключённый Redis позволяют запустить сервис без инфраструктуры, но ответы строит
GigaChat: пока не задан `GIGACHAT_CREDENTIALS`, на каждый запрос приходит сообщение
«GigaChat не настроен…», а в лог пишется предупреждение.

Для разработки фронтенда: `cd frontend && pnpm dev` — Vite поднимается на
`http://localhost:5173` и проксирует `/api` и `/ws` на приложение. Production-сборка
(`pnpm build`) кладётся в `frontend/dist`, её раздаёт FastAPI.

### 2. Голос

Нужен `ffmpeg` в системе и модель Vosk:

```bash
curl -L https://alphacephei.com/vosk/models/vosk-model-small-ru-0.22.zip -o /tmp/vosk.zip
unzip -q /tmp/vosk.zip -d models/
```

Голосовые сообщения принимаются в Telegram,VK, MAX и в веб-интерфейсе (кнопка записи).
Распознавание выполняет официальный Python-биндинг Vosk из
[alphacep/vosk-api](https://github.com/alphacep/vosk-api) (`vosk==0.3.45`): файлы и живой поток
идут через один и тот же `KaldiRecognizer`.
Веб-клиент стримит PCM 16 кГц по WebSocket `/ws/voice`: Vosk распознаёт чанки по мере речи,
поэтому финальный текст готов к моменту окончания записи. При недоступности WebSocket
клиент откатывается на отправку файла в `/api/voice`.
Без модели текстовые сценарии продолжают работать, на голос ассистент отвечает просьбой
написать текстом.

### 3. GigaChat и SaluteSpeech  

* `GIGACHAT_CREDENTIALS` — Authorization key из кабинета developers.sber.ru (scope `GIGACHAT_API_PERS`).
* `CLOUD_TTS_API_KEY` — ключ Cloud.ru Foundation Models: через него работает SaluteSpeech
  (`wss://foundation-models.api.cloud.ru/v1/realtime`, модель `GigaChat/SaluteSpeech`, голос `Mer-Operator`).
* `SBER_TTS_CREDENTIALS` — прямой gRPC-ключ SaluteSpeech (scope `SALUTE_SPEECH_PERS`), резервный путь
  при `TTS_BACKEND=sber`; `TTS_BACKEND=local` оставляет офлайновый espeak-ng.
* Для запросов к API Сбера нужен корневой сертификат Минцифры: установите его в систему либо
  укажите `SBER_CA_BUNDLE=/путь/к/сертификату.pem`. `GIGACHAT_VERIFY_SSL=false` — только для отладки.
* Миграции: `alembic upgrade head`. `AUTO_CREATE_TABLES=true` создаёт схему с нуля по моделям —
  это режим для чистой локальной базы; уже существующую базу обновляет только
  `alembic upgrade head` (контейнер выполняет её при старте).

### 4. Гостевой режим, вход по почте и паролю, привязка аккаунтов

Веб-версия открывается без входа: браузер сразу получает гостевой аккаунт, и задачи
сохраняются в нём. Чтобы открывать те же задачи на другом устройстве, задайте в настройках
(шестерёнка в шапке) почту и пароль — они привязываются к текущему аккаунту, история остаётся
на месте. Тем же адресом и паролем входят на другом устройстве.

Боты и мини-приложения Telegram, ВКонтакте и MAX заводят аккаунт по данным платформы — без
почты и пароля. Почта и пароль добавляются в настройках приложения; после этого аккаунт
открывается в веб-версии. Обратное тоже работает: вход по почте и паролю из мини-приложения
сам привязывает платформу к тому же аккаунту, а события, созданные в боте, переезжают в него.

`SESSION_SECRET` подписывает токены сессий; пароли хранятся как salted scrypt-хеши
(`app/services/auth/passwords.py`). Письма не отправляются: адрес почты не подтверждается.

Новый аккаунт — гость в браузере, первый запуск мини-приложения, первый запрос боту —
создаётся с примерами: встречи, задачи и напоминания на ближайшую неделю, одна встреча
повторяется каждую неделю (`app/services/demo_seed.py`). Так календарь и диаграмма Ганта
показывают работающий сценарий сразу, без ручного заполнения (в чате записи видны в ответ на
«Что у меня сегодня?»). Заполнение отключается `DEMO_SEED_ENABLED=false`.

### 5. Полный стек (PostgreSQL + Redis + приложение)

```bash
cp .env.example .env   # заполните токены ботов и API
docker compose up --build
```

Модель Vosk скачивается на этапе сборки образа; контейнер при старте применяет
`alembic upgrade head` — так стенд не зависит от сети в момент запуска.
Образ собирается в два этапа: Node-стадия выполняет `pnpm build`, готовая SPA попадает
в `frontend/dist` внутри контейнера.

### 6. Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest -q        # 315 passed, 1 skipped

cd frontend && pnpm test   # 181 passed
```

## ✅ Что реализовано
[К содержанию](#toc)

Четыре обязательных сценария работают в каждом интерфейсе:

1. Создание задачи или напоминания — «Напомни завтра в 10 позвонить Ивану».
2. Создание встречи — «Добавь встречу с командой завтра в 15:00»; без времени ассистент
   задаёт уточняющий вопрос и не создаёт запись.
3. Список записей за период — «Что у меня сегодня?», «Что запланировано на эту неделю?».
4. Поиск старых записей — «Найди задачу про презентацию», «Когда у меня была встреча с Иваном?».

Дополнительно:

* изменение и удаление записей, отметка выполненной;
* предупреждение о конфликте встреч (в это же время уже есть встреча);
* контекст диалога: последние реплики хранятся в Redis и передаются в LLM;
* напоминания по времени через планировщик, доставляются в Telegram, ВКонтакте и MAX;
* кэширование списков событий в Redis с инвалидацией при записи;
* кнопки быстрого доступа в Telegram;
* потоковое распознавание речи в веб-интерфейсе: чанки аудио уходят в `/ws/voice`,
  промежуточный текст показывается во время речи;
* карточки действий в чате: тип, время и статус записи, кнопка «выполнено» — в веб-интерфейсе,
  Telegram и MAX (inline-кнопка в боте);
* экспорт всех записей в календарь файлом `.ics` (ICS с повторами и напоминаниями) — кнопка в
  календаре, эндпоинт `GET /api/calendar/export.ics`;
* режим диалога голосом в браузере: микрофон открывается один раз, ответы озвучиваются,
  перебивание голосом и фраза прощания закрывают диалог (`frontend/src/hooks/useVoiceConversation.ts`);
* три режима веб-интерфейса: чат, календарь и диаграмма Ганта. Гант показывает период на
  2 недели или месяц, раскрывает повторяющиеся события на каждом вхождении, подсвечивает
  сегодняшний день и открывает карточку записи по клику на полосу; дни не сжимаются —
  длинный период листается вбок, колонка названий и шапка остаются на месте
  (`frontend/src/components/GanttView.tsx`, `frontend/src/lib/gantt.ts`). Весь интерфейс
  занимает ширину окна: чат держит читаемую колонку по центру, календарь и Гант растягиваются
  на весь экран.

HTTP API веб-интерфейса:

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/` | страница чата (React SPA) |
| GET | `/api/meta` | часовой пояс и быстрые действия для интерфейса |
| POST | `/api/chat` | текст: `{"text": "...", "speak": false, "closing": false}`; `speak: true` возвращает озвучку ответа, `closing: true` — прощание вместо создания события |
| POST | `/api/chat/warmup` | прогрев модели системным промптом до первой реплики (`{"status": "ok", "warmed": true}`) |
| POST | `/api/voice` | аудио: multipart `audio` |
| POST | `/api/speech` | озвучка произвольного текста: `{"text": "...", "voice": "Mer-Operator"}` → base64 opus |
| POST | `/api/telemetry` | диагностика клиента: `{"event": "...", "phase": "...", "detail": "..."}`, пишется в лог |
| GET | `/api/calendar/export.ics` | выгрузка всех записей в файл календаря (ICS) |
| GET | `/api/events?period=today\|tomorrow\|week\|all` | список записей |
| POST | `/api/events/{id}/complete` | отметить выполненной |
| WS | `/ws/voice` | потоковое распознавание: первым кадром `{"type":"auth","token":"..."}`, далее PCM 16 кГц, `{"type":"stop"}`; события `ready`/`partial`/`final`/`error` |
| POST | `/api/auth/guest` | гостевой аккаунт для браузера без входа |
| POST | `/api/auth/register` | `{"email": "...", "password": "..."}` — зарегистрировать почту и пароль; с токеном текущей сессии адрес привязывается к этому аккаунту и его события сохраняются |
| POST | `/api/auth/login` | `{"email": "...", "password": "..."}` — войти и привязать текущую платформу к аккаунту |
| POST | `/api/auth/session` | вход из мини-приложения: `{"platform": "telegram\|max\|vk", "payload": "..."}` → токен, личность, привязанные платформы |
| GET | `/api/auth/me` | текущий аккаунт по токену сессии (`email`, `has_password`, привязанные платформы) |
| GET | `/healthz` | проверка живости |

Запросы к API требуют `Authorization: Bearer <token>`, кроме `/healthz`, `/api/meta`,
`/api/telemetry` и `/api/auth/*`; поток распознавания получает тот же токен первым кадром
`{"type":"auth","token":"..."}`. Личность берётся только из подписанного
токена, клиентский идентификатор не принимается.

### Интерфейсы и вход
[К содержанию](#toc)

Ассистент работает в четырёх местах, и во всех это один и тот же аккаунт:

| Интерфейс                           | Реализация |
|-------------------------------------| --- |
| Telegram-бот `@hackathon_helperbot` | aiogram, long polling, текст и голосовые |
| ВКонтакте `@hackathon_helperbot`    | vkbottle, Long Poll, текст и голосовые |
| MAX `@se14503983_bot`               | собственный клиент Bot API, long polling |
| Веб `https://gorkycode.cc-data.ru/` | React SPA + FastAPI |

Мини-приложения Telegram, ВКонтакте и MAX открывают один и тот же SPA. Приложение
определяет платформу, забирает launch-данные (Telegram `initData`, MAX WebApp
`initData`, VK `vk_*` вместе с `sign`) и меняет их на подписанный токен сессии:

* Telegram — HMAC-SHA256 от `initData` с ключом из токена бота;
* MAX — та же схема с ключом `WebAppData`, как в MAX Bridge;
* ВКонтакте — HMAC-SHA256 подписи `sign` с секретом мини-приложения.

Подпись и срок жизни launch-данных проверяет `app/services/auth/launch.py`, токен
сессии выпускает `app/services/auth/tokens.py`. Аккаунты связываются только почтой и
паролем: `POST /api/auth/register` добавляет вход к текущему аккаунту,
`POST /api/auth/login` привязывает платформенную личность к аккаунту с этим адресом,
после чего история переезжает в него (`app/repositories/account_repository.py`).
Браузерная сессия стартует гостевой через `POST /api/auth/guest`; боты и мини-приложения
заводят аккаунт по данным платформы. Ссылки мини-приложений (`https://t.me/<bot>`,
`https://max.ru/<bot>`, `https://vk.com/app<id>`) отдаёт поле `mini_apps` в ответе
auth-эндпоинтов. Переменные окружения перечислены в `.env.example`.

Что нужно включить на стороне платформ:

| Интерфейс | Что требуется |
| --- | --- |
| Telegram-бот | `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME`; меню-кнопка ставится через Bot API, домен мини-приложения подтверждается в BotFather |
| Telegram-мини-приложение | `WEB_PUBLIC_URL` и `MINI_APP_PUBLIC_URL` с https; домен регистрируется в BotFather (Mini App) |
| MAX-бот | `MAX_BOT_TOKEN`, `MAX_BOT_USERNAME` |
| MAX-мини-приложение | мини-приложение, привязанное к боту в кабинете MAX; открывается по ссылке `https://max.ru/<bot>` |
| ВК-бот | `VK_BOT_TOKEN` с правами «Сообщения сообщества» и «Управление сообществом», в сообществе включён Long Poll API |
| ВК-мини-приложение | `VK_MINI_APP_ID`, `VK_MINI_APP_SECRET` — без них проверка подписи launch-данных недоступна и вход из ВК не работает |

## 🧩 Как устроен пайплайн
[К содержанию](#toc)

`аудио → AudioConverter (16 кГц WAV) → Vosk → AssistantService → GigaChat (function calling) →
ToolExecutor → EventRepository → ответ → SaluteSpeech → аудио`

* `AssistantService` — единственная точка входа для интерфейсов: строит ответ через GigaChat,
  ведёт историю диалога и синтез речи.
* `ToolExecutor` выполняет вызовы инструментов над репозиториями одного пользователя.
  Инструменты: `create_task`, `create_meeting`, `list_events`, `search_events`, `update_event`,
  `complete_event`, `delete_event`.
* `EventRepository` отдаёт выборки по периоду и поиск по названию/описанию: словоформы,
  словарь синонимов и сокращений («тз» → «техническое задание», «созвон» → «звонок»),
  нормализация «ё» и ранжирование по релевантности, а не по дате.
* `ReminderService` — asyncio-цикл, который выбирает созревшие напоминания и передаёт их
  нотификаторам интерфейсов; `reminder_sent_at` защищает от повторной доставки.

Даты в БД хранятся в UTC без часового пояса, в человеческий вид переводятся в `app/core/timeutils.py`
по `TIMEZONE` (по умолчанию `Europe/Moscow`).

**Что решает код, а не модель.** `app/ai/nlp/ru_time.py` разбирает «завтра», «в четверг», «через
два часа», «15 ноября», «до конца недели» и время суток в абсолютную дату и время. Поэтому день
недели не зависит от арифметики модели, а вопрос «во сколько?» задаётся только тогда, когда
пользователь действительно не назвал время: придуманное моделью время не проходит. `app/ai/nlp/scope.py`
до вызова модели отказывает просьбам вне продукта (рецепты, код, «игнорируй инструкции»), а
`app/ai/llm/replies.py` вычищает из ответа случайно сериализованный вызов инструмента и не пускает
его в историю диалога — иначе модель повторяет такую форму в следующих репликах.

## 💡 Решения, принятые самостоятельно
[К содержанию](#toc)

* **Без демо-разборщика.** Единственный путь ответа — GigaChat с function calling: прототип
  не подменяет модель регулярками, а без токенов возвращает сообщение о настройке.
* **Семь инструментов вместо четырёх.** Исходное описание перечисляло создание, список и поиск;
  добавлены изменение, отметка выполнения и удаление — это закрывает бонусные сценарии.
* **Redis как хранилище истории диалога.** Кэш списков событий и история реплик живут в одном
  сервисе; при недоступности Redis он переключается на память процесса, приложение не падает.
* **Напоминания на asyncio, без APScheduler.** Для одной задачи планировщика хватает цикла с
  настраиваемым интервалом — меньше зависимостей и предсказуемое поведение.
* **Поиск: словоформы и синонимы, без эмбеддингов.** Запрос разбивается на слова, отбрасываются
  служебные, к каждому слову добавляются усечённые варианты, варианты с «ё» и синонимы
  («тз» → «техническое задание», «договор» → «контракт»), а результаты сортируются по
  релевантности: совпадение в названии весит больше, чем в описании, тип записи из запроса
  («встреча», «задача») добавляет вес. Поэтому «Иваном» находит «встреча с Иваном», а
  «подготовь тз» — «Подготовить техническое задание».
* **Длительность встречи** хранится строкой в описании: отдельная колонка не понадобилась.

## 🔭 Ограничения и что улучшил бы дальше
[К содержанию](#toc)
 
* Vosk small-модель путает имена и термины; для качества нужен больший офлайн-модель.
  Потоковое распознавание работает в вебе, боты по-прежнему присылают файл целиком.
* Надёжность function calling зависит от GigaChat: цикл ограничен четырьмя итерациями, при
  ошибке инструмента ассистент задаёт уточняющий вопрос; если модель падает уже после
  выполнения действия, пользователь получает результат действия, а не сообщение об ошибке.
* Веб-канал не получает push-напоминания: нотификаторы зарегистрированы для Telegram,
  ВКонтакте и MAX. Напоминание, созданное в вебе, видно в списке, но уведомление по нему
  приходит только в привязанный мессенджер.
* Повторение поддержано в объёме RRULE (ассистент ставит `FREQ=WEEKLY`, повторы раскрываются в
  календаре и на диаграмме Ганта), но интерфейса для правки правила нет; интеграции с внешними
  календарями, кроме выгрузки `.ics`, нет. Поиск остаётся словарным: словоформы и синонимы
  покрывают типичные переформулировки, но не свободные парафразы — следующий шаг — эмбеддинги
  GigaChat и гибридный ранжировщик.
* Аккаунт без почты живёт только в браузере (localStorage): очистка хранилища закрывает доступ
  к нему. Письма не отправляются, поэтому адрес почты не подтверждается и восстановления
  пароля нет.
* Нет метрик и трассировок: добавление OpenTelemetry и кэша синтеза речи — следующие шаги.
* MAX использует long polling (для production нужен webhook), Telegram — polling.
* Конфликт встреч только обнаруживается и озвучивается: слот не резервируется и не запрещается.

### 1. AI, Голос и LLM
**Участники:** `@FreezeEngine`, `@semyoonov`, `@IGapone`
